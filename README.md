# AI Playbook

**One person's AI journey, written down so other people can use AI for their
own projects.**

I am learning AI by practicing it — on real ministry, business, and creative
work — and recording what actually happens: what I built, what worked, what
broke, and the principles I would hand to someone starting today. Everything
is explained top-down (the whole picture first, then the parts) and in plain
words, assuming nothing — not even what GitHub is.

## The whole picture, on one page

Everything in this playbook hangs on one simple architecture:

- **A personal agent** — an AI assistant that knows you and does real work
  with you, not just answers questions.
- **A memory it can keep** — files *you own* that hold who you are and how
  you work, so the agent does not start from zero every conversation.
- **Project tracking** — a separate place for the changing details of each
  project, kept apart from the durable memory.
- **One room per project** — separate conversations for separate projects,
  so each one stays deep and uncluttered; a main conversation routes work
  between rooms and reviews the whole.
- **GitHub underneath** — the filing cabinet where all of it lives as
  plain-text files you control.

## How this repository is maintained

It is **AI-native**: AI agents maintain and improve it under the owner's
direction, following the contract in [AGENTS.md](AGENTS.md), the live status
in [STATE.md](STATE.md), and the machine-readable inventory in
[index.json](index.json). The owner approves every commit. Articles are
numbered permanently and written to be safe to share: no private details,
ever.
