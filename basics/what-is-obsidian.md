# What Is Obsidian?

## In one sentence

Obsidian is an app for notes and knowledge that keeps everything as plain
Markdown files in a folder on your own computer — linked together into a
web you own outright.

## In plain words

Most note apps store your words inside *their* system, on *their*
servers, in *their* format. Obsidian inverts that. Your notes are ordinary
`.md` text files (see [Markdown](../glossary.md)) sitting in a folder on
your machine called a **vault**. Obsidian is a powerful window onto that
folder — if the app vanished tomorrow, your notes would still be there,
readable by anything.

What makes it more than a text editor is the **linking**. Type
`[[another note]]` and the two notes are connected; Obsidian shows you the
backlinks (every note that points at this one) and can draw the whole web
as a graph. Knowledge stops being a pile of documents and becomes a
network: a person links to their projects, a project to its meetings, a
meeting to its decisions.

Around that core sits a large community ecosystem of plugins that extend
it — calendars, task boards, databases made of notes — plus optional paid
services for syncing between devices and publishing to the web. The core
idea never changes, though: **local files first, yours forever.**

## A tiny example

A ministry leader keeps a vault for her church: a note for every leader,
every group, every recurring meeting. The "Fall Groups" note links to each
leader's note; each leader's note links back to their group and its health
notes. Six months later she asks, "which groups have I not checked on this
month?" — and the web answers, because the structure was built one honest
link at a time. That pattern, grown up, is an operations system — and it is
exactly what Series 3 of this playbook is about.

## Why it matters in this playbook

Obsidian is [Pattern 1](../patterns.md) — *context is infrastructure you
own* — in application form. It is the natural companion to everything here:

- Its files are plain Markdown, the same format this playbook, the
  Personal Context OS, and agent context files are written in. An agent
  that can read your repository can read your vault.
- It works entirely offline and locally, so sensitive working notes —
  ministry, family, drafts — can live in a system that never sends them
  anywhere.
- It pairs with [GitHub](what-is-github.md): a vault is just a folder of
  text files, so it can be versioned and backed up like any repository.

Series 3, *AI for Ministry Operations*, builds on Obsidian directly:
using a vault as a church's operations knowledge base, with an agent's
help to maintain it.

## Common confusions

- **Obsidian is not a cloud notes service.** Sync exists, but as an
  optional add-on. The default is: your computer, your files.
- **The graph view is not the point.** The pretty web picture is a poster;
  the value is in the daily habit of linking notes as you write them.
- **It is not only for "note-taking."** With links, templates, and
  plugins, a vault becomes a lightweight operating system for a project, a
  ministry, or a life's work — which is why it earns a place in a playbook
  about systems.
